01先搞清楚这个项目到底是什么

很多人做完项目说不清自己在做什么。你先把这个定义背下来：

一句话定义

这是一个 零后端、单文件、可离线运行的三维地质数据可视化前端，加一套 离线空间分析预处理管线。数据全部在构建期由 Python 算好并编码成 JS 文件，浏览器端只负责解码、建网格、着色、交互。

理解了这个定义，你就明白为什么项目里没有 Node、没有数据库、没有 API——这是刻意的架构选择，不是偷懒。它带来的好处是部署成本为零（一个 HTML 丢到任何静态服务器就能跑），代价是所有分析必须在构建期完成，无法实时查询。

数据流向（记住这条链）

原始 DEM (.hgt/.tif)  ──┐
矿点/县界 (SHP)       ──┼─→  Python 预处理脚本  ──→  *.js (window.XXX 全局挂载)
遥感影像 (STAC COG)   ──┘         (离线算完)              ↓
                                                   浏览器端解码
                                                        ↓
                                              Cesium 自建 Primitive
                                                        ↓
                                                GLSL 着色器上色

03优先级排序：什么必学、什么知道就行

你时间有限，战线不能再铺。按"通用性 × 简历含金量 × 迁移成本"三个维度排序：

P0 必须真正掌握（学完能直接换工作用）

技术点为什么是 P0
GIS 空间分析算法Gi* 冷热点、NNI、核密度、泰森多边形——这是你作为 GIS 专业学生的护城河。纯程序员不会这个，会这个的又不会写代码。你两边都沾，这是最稀缺的组合。要求：能手推公式、能解释 z 得分和 p 值的含义、知道什么数据该用什么方法。
rasterio + numpy 栅格处理遥感/GIS 岗位的硬技能。重采样、重投影、窗口读取、nodata 处理、掩膜运算——这些是每天都在用的基本功。本项目 build_dem_terrain.py 就是一份完整的范例。
WebGL / GLSL 着色器基础不需要你成为图形学专家，但要能读懂并改顶点/片元着色器。因为现在所有高性能地图库（Cesium、Mapbox GL、Deck.gl）底层都是它。会改 shader 的前端，薪资档位不一样。

05五个核心知识点拆解

5.1 数据体积优化：为什么 4.1 MB 的 DEM 能塞进浏览器

原始 DEM 是 .hgt 栅格，直接转 JSON 会是几十 MB。项目用了三层压缩：

脚本/build_dem_terrain.py:165-167
enc = np.round((np.nan_to_num(heights, nan=0.0) - hmin) * 10.0).astype(np.uint16)
hb64 = base64.b64encode(enc.tobytes()).decode("ascii")
mb64 = base64.b64encode(pack_bits(mask).tobytes()).decode("ascii")
手段原理收益
定点量化高程减去最小值后 ×10 取整，存 uint16。0.1 m 精度对地形可视化完全够用float64 → uint16，4 倍
位打包掩膜有效性是 0/1，用 1 bit 存一个格点，1 字节存 8 个8 倍
JPEG 纹理山体阴影是灰度图，转 JPEG data URI 内联避免额外 HTTP 请求

通用价值：这套"降精度 → 改编码 → 位压缩"的思路，在任何"要把科学数据搬到前端"的场景都适用（气象场、污染扩散、人口栅格）。记住这个模式，比记住这几行代码重要。

5.2 栅格重采样：双线性插值 + 螺旋回退

浏览器拿到的是 1024×1024 网格，但矿点/标注的经纬度是任意浮点数。需要插值取高程：

赣南矿脉_数字孪生大屏.html:460-483
function sampleRaw(lon, lat){
  var fx = (lon - DM.west)  / (DM.east  - DM.west)  * (GW - 1);
  var fy = (DM.north - lat) / (DM.north - DM.south) * (GH - 1);
  if (fx < 0 || fx > GW - 1 || fy < 0 || fy > GH - 1) return null;
  var i0 = Math.floor(fx), j0 = Math.floor(fy);
  var i1 = Math.min(i0 + 1, GW - 1), j1 = Math.min(j0 + 1, GH - 1);
  var dx = fx - i0, dy = fy - j0;
  var acc = 0, wsum = 0;
  var cs = [[i0,j0,(1-dx)*(1-dy)],[i1,j0,dx*(1-dy)],[i0,j1,(1-dx)*dy],[i1,j1,dx*dy]];
  for (var c = 0; c < 4; c++){
    if (maskAt(cs[c][0], cs[c][1])){ acc += rawH(cs[c][0], cs[c][1]) * cs[c][2]; wsum += cs[c][2]; }
  }
  if (wsum > 0.01) return acc / wsum;
  // 四邻都是空洞 → 螺旋向外搜第一个有效点
  for (var r = 1; r < 30; r++){ /* ... 环形扫描 ... */ }
  return DM.minH;
}

两个关键点：① 权重只累加有效格点（wsum 动态归一化），避免 nodata 污染结果；② 四邻全空时螺旋外扩搜索兜底。这就是"算法 + 工程兜底"的完整思维——教科书只讲前半段，真正上线必须写后半段。

5.3 规则网格 → GPU 三角网

Cesium 自带的 createWorldTerrain 需要联网，且无法自定义着色。项目选择自建 Primitive：

赣南矿脉_数字孪生大屏.html:513-547（节选）
function buildTerrainGeometry(){
  // 先数有效格点，一次性分配定长 TypedArray（避免 push 扩容）
  var count = 0;
  for (k = 0; k < GW * GH; k++) if ((_mb[k >> 3] >> (k & 7)) & 1) count++;

  var vid = new Int32Array(GW * GH).fill(-1);   // 格点 → 顶点索引映射
  var pos = new Float64Array(count * 3);
  var st  = new Float32Array(count * 2);        // 纹理坐标
  var hgt = new Float32Array(count);            // 高程（单独传，供 shader 夸张）

  /* Pass 1: 标记所有有效四边形 —— 四角都有效才生成面 */
  for (j = 0; j < QH; j++) for (i = 0; i < QW; i++){
    if (vid[j*GW+i] < 0 || vid[j*GW+i+1] < 0 ||
        vid[(j+1)*GW+i] < 0 || vid[(j+1)*GW+i+1] < 0) continue;
    qok[j*QW+i] = 1; nq++;
  }

三个值得记住的设计：
① vid 索引表把二维格点映射成一维顶点数组，是栅格转矢量的标准手法；
② 高程 hgt 单独作为顶点属性传给 shader，而不是直接算进 position——这样调整垂直夸张时不用重建几何；
③ 边缘生成 skirt（裙边，向下延伸 4000 m），堵住网格侧面的缝隙，避免从低角度看到"纸片"。

5.4 着色器：地形是怎么被"画"出来的

顶点着色器只做一件事——按垂直夸张抬高顶点：

赣南矿脉_数字孪生大屏.html:631-640
void main() {
    vec3 pw = position3DHigh + position3DLow;   // 双精度拆分：高位+低位
    vec3 up = normalize(pw);                     // 该点的"天顶"方向
    vec3 p  = pw + up * (height - u_hmin) * (u_exag - 1.0);
    v_st = st;   v_h  = height;
    vec4 clip = czm_viewProjection * vec4(p, 1.0);
    v_dist = clip.w;   // 传给片元着色器做距离雾/等高线宽度
    gl_Position = clip;
}

片元着色器叠了四层效果，顺序很讲究：

赣南矿脉_数字孪生大屏.html:697-721（节选）
void main() {
    float t = clamp((v_h - u_hmin) / max(u_hmax - u_hmin, 1.0), 0.0, 1.0);
    vec3 col;   // ① 按 u_demPal 选色带（4 套配色用一个 float uniform 切换）
    if (u_demPal < 0.5) col = rampTerrain(t);
    else if (u_demPal < 1.5) col = rampElev(t);
    else if (u_demPal < 2.5) col = rampGray(t);
    else col = rampGreen(t);

    // ② 叠加山体阴影纹理（乘性混合，保留色相只改明暗）
    float hs = texture(u_hillshade, v_st).r;
    col *= mix(1.0 - u_hs, 1.0 + u_hs * 0.85, hs);

    // ③ 屏幕空间等高线：宽度随距离自适应（mpp = meters per pixel）
    if (u_contour > 0.5) {
        float mpp = max(v_dist * u_px, 0.6);
        float d2 = abs(fract(v_h / 200.0 + 0.5) - 0.5) * 200.0;
        float l2 = 1.0 - smoothstep(mpp * 0.7, mpp * 1.8, d2);
        col = mix(col, col * 1.32 + vec3(0.05, 0.04, 0.02), l2 * 0.55);
        /* 1000m 主等高线同理 */
    }

    // ④ 距离雾：远处融入天空色，制造纵深
    float fog = clamp((v_dist - u_fogNear) / max(u_fogFar - u_fogNear, 1.0), 0.0, 1.0);
    col = mix(col, u_fogColor, fog * 0.88);
    out_FragColor = vec4(col, u_alpha);
}

这里最值得学的是第 ③ 步：等高线不是预先生成的矢量，而是用 fract(v_h / 200.0) 在片元级别实时算的。而且线宽用 mpp（每像素代表多少米）做自适应——远处线不会糊成一片。这是屏幕空间算法的典型思路，在地图渲染里到处都是。

5.5 高度一致性：CPU 和 GPU 必须算同一个数

这是本项目最后、也最隐蔽的一个 bug，值得单独记：

问题现象

矿点标记"浮"在空中，加 disableDepthTestDistance 强行穿透后，又看起来像贴在玻璃上。

根因

地形网格的几何高度是 surfaceH(..., AL_LIFT=70)，顶点着色器又额外抬了 (height - hmin) × (EXAG - 1)。而矿点标记只放在 surfaceH(..., 0) + 6，比真实地形顶面低了 375 m——被埋在地形里了。

解法

写一个函数精确复刻 GPU 侧的计算：

赣南矿脉_数字孪生大屏.html:493-497
// 地形真实顶面椭球高：几何 height=surfaceH(...,AL_LIFT)，
// 顶点着色器再抬 (H-DM.minH)*(EXAG-1)
function terrainTopH(lon, lat){
  var H = surfaceH(lon, lat, AL_LIFT);
  return H + (H - DM.minH) * (EXAG - 1.0);
}

然后在 applyLift() 里，垂直夸张滑块一变就重算所有标记高度，保证永远贴合。

通用教训：凡是用 shader 改了几何外观，CPU 侧所有依赖位置的逻辑（贴地、拾取、碰撞、标注）都必须同步这个变换。这类 bug 不报错、不崩，只是"看起来不对"，是最难查的一类。以后做 3D 项目，第一时间把这个对照关系写清楚。

06Cesium 三大坑（踩过的才值钱）

这三条是本项目实打实撞出来的，网上文档基本不写。面试时随口说一条，就能证明你是真做过而不是抄的。

坑 1：Appearance 基类不保存 options.uniforms

你以为 new Cesium.Appearance({ uniforms: {...} }) 会把 uniforms 存下来，不会。必须在创建后手动赋值：

var app = new Cesium.Appearance({ /* ... */ });
app.uniforms = { u_demPal: function(){ return 0.0; }, /* ... */ };  // 手动补

坑 2：getUniformFunction 会再包一层

uniform 的值必须是普通值或返回值的函数。如果你传了函数，Cesium 会再包一层，导致 mu.value 变成函数对象而不是数值。表现为"改了 uniform 没反应"，且不报错。

坑 3：拾取通道会自动引用 batchId

自定义几何的着色器里必须声明 in float batchId 并提供对应的 Float32Array 属性（全 0 即可），否则 pick 通道编译失败。或者干脆 allowPicking: false 跳过拾取通道：

'in float batchId;',   // 即使不用也要声明

07学习路径建议

按你"项目驱动、手写吃力、需要收敛"的特点排的。一次只走一条线，不要并行。

第一步：把空间分析算法补成"能讲"1–2 周

这是最高性价比的一步——你是 GIS 科班，补理论比补编程快。

  • 把 脚本/spatial_analysis.py 里每个方法对应的数学公式手写一遍（Gi* 统计量、NNI 比值、Moran's I）
  • 能回答：z 得分多大算显著？p 值需要多重检验校正吗？为什么要用置换检验？
  • 能回答：什么情况下该用核密度，什么情况下该用 Gi*？二者结论冲突时信谁？

第二步：GLSL 着色器1 周

不需要系统学图形学，就对着本项目这两个 shader 改。

  • 目标：能自己加一套新的 DEM 配色（照抄 rampGreen 改改颜色值）
  • 目标：能改等高线间距（把 200/1000 改成 100/500）
  • 推荐资料：WebGL Fundamentals（在线教程，讲清管线），不用碰 OpenGL 大部头

第三步：rasterio 栅格处理做成肌肉记忆持续

  • 照着 build_dem_terrain.py 独立写一个"任意 DEM → 前端可用数据包"的通用脚本
  • 重点练：窗口读取（大文件不整读）、重投影、nodata 统计式填充

第四步（可选）：补一个现代前端框架有余力再做

本项目是原生 JS 单文件。找工作时如果投前端/WebGIS 岗，Vue 或 React 至少要能写。但优先级低于前三步——算法和图形学是你的差异化优势，框架谁都能学。

提醒：你容易开局热情高、卡在调试。所以每一步都定一个可验收的最小产物——比如第一步的产出物就是"一份手写的公式推导笔记 + 三个方法的对比表"。做出来就算过，不要追求完美。

高频追问，提前准备好答案

可能会被问你该怎么答（要点）
为什么不用 Cesium 自带地形？需要联网、无法自定义着色、精度不可控。科研可视化要求离线可复现 + 可定制配色，所以自建。
等高线为什么不用矢量数据？矢量等高线是固定尺度的，缩放会失真。用 shader 在片元级实时计算，线宽按每像素米数自适应，任何缩放级别都清晰且零数据体积。
数据压缩会损失精度吗？会，但可控。0.1 m 量化误差对区域尺度地形可视化无影响。关键是要说明你评估过这个取舍，不是随便压的。
Gi* 和核密度有什么区别？核密度只描述"密集程度"，是描述性统计；Gi* 是推断统计，给出 z 得分和显著性，能回答"这个聚集是不是偶然的"。做结论要用 Gi*。
遇到过最难的技术问题？讲 5.5 那个高度一致性 bug——现象不报错只是"看起来不对"，定位到 CPU/GPU 高度公式不一致。这类问题能体现调试深度。
